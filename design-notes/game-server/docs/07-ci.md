# 07 — CI and reproducibility

CI for `iouring-net-server`. The trickier-than-library concern: the
product depends on a versioned install of `iouring-net-lib`, so every
job has a **library build/install step before** the product build/test
step. This document specifies how the library tag is pinned, how the
install is sandboxed, and how the CI matrix maps to the test layers
from [`06-test-strategy.md`](06-test-strategy.md).

---

## Job topology

```
on: pull_request / push to main
  ↓
  ┌─────────────────────────────────────────────────────────────────┐
  │ build-and-test (matrix: preset × distro)                         │
  │                                                                  │
  │  step 1: checkout iouring-net-lib @ ${LIB_TAG}  (cached)         │
  │  step 2: cmake + build + install to $RUNNER_TEMP/prefix          │
  │  step 3: checkout iouring-net-server (current PR)                │
  │  step 4: codegen (configure-time, automatic)                     │
  │  step 5: cmake -DCMAKE_PREFIX_PATH=$RUNNER_TEMP/prefix           │
  │  step 6: build                                                   │
  │  step 7: ctest -L "unit|integration"                             │
  └─────────────────────────────────────────────────────────────────┘

on: schedule (nightly)
  ↓
  ┌──────────────────────────────┐  ┌──────────────────────────────┐
  │ e2e-replay                    │  │ fuzz                          │
  │ ctest -L e2e                  │  │ run libFuzzer for 30 minutes  │
  └──────────────────────────────┘  └──────────────────────────────┘
```

## Library-tag pinning

The library version is pinned in **two places**, kept in sync:

1. **`.github/workflows/build.yml`** — `LIB_TAG: v0.0.1`
2. **`docs/00-overview.md`** — "Toolchain" section, version line.

A bot (or a script) re-pins both when bumping. The library is never
floated to `main` — that defeats the "reproducible product build"
property.

The pin is by **git tag**, not by version number, because:
- A tag has a single commit, single tree, single install.
- The version number embedded in
  `iouring_netConfigVersion.cmake` could match multiple commits (any
  commit at version `0.0.1`); the tag is unambiguous.
- `find_package(iouring_net 0.0.1 REQUIRED)` is the consumer's
  *minimum*, not the CI's *pin*. They are different mechanisms.

### Cache strategy

The library's `cmake --install` output is content-addressable by
tag + compiler + sanitizer preset. Cache key:
```
iouring-net-lib-${LIB_TAG}-${PRESET}-${CC_VERSION}-${OS}
```

A cache hit skips the library build entirely, saving ~90 seconds per
job. Cache miss triggers a full library build + install before the
product builds.

The `floor-jammy` job is the **reproducibility anchor**: a stock
22.04 box with no PPAs, no Docker, just `apt install` deps. If this
job goes red, the floor has slipped.

The `clang-noble` job exists because the library's clang job exists
(and the warning sets diverge between gcc and clang); without it,
clang regressions land silently.

## Reproducibility envelope

Same model as the library — see
[`iouring-net-lib/docs/07-ci-and-reproducibility.md`](../../../engine-uring/doc/07-ci-and-reproducibility.md).
The product extends the envelope with:

| Anchor                          | Purpose                                                              |
|---------------------------------|----------------------------------------------------------------------|
| Library git tag                 | The exact library source the product was built against               |
| Library install snapshot SHA    | Hash of `lib/cmake/iouring_net/iouring_netTargets.cmake`             |
| Python version                  | `python3 --version` recorded in `version-snapshot.txt`               |
| Schema SHA                      | SHA-256 of `proto/packets.json` after normalization                  |
| Generated SHA                   | SHA-256 of concatenated `generated/*.h` and `*.cpp`                  |

The generated-files SHA is the codegen determinism check: if
schema-SHA matches but generated-SHA doesn't, a generator has gained
nondeterminism (bug; block release).

A `scripts/emit-snapshot.sh` (to be ported from
[`iouring-net-lib/scripts/emit-snapshot.sh`](../../../engine-uring/scripts/emit-snapshot.sh))
emits this into `build/version-snapshot.txt` and CI uploads it as a
job artifact.

## Devcontainer / Docker (CI flavor)

CI does not use the dev devcontainer. It uses a leaner workflow image
that:
- Installs only build deps (no editor tooling).
- Pre-installs the library at the pinned tag into `/usr/local`.
- Is pinned by digest (not tag) so the CI runtime is bit-stable.

Image build cadence: weekly, plus on `LIB_TAG` bump. The image-build
workflow lives in `.github/workflows/image-build.yml` and pushes to
`ghcr.io/<org>/iouring-net-server-ci`.

The image is **not** used for `floor-jammy`. That job runs on a stock
GitHub-Actions Ubuntu 22.04 runner with `apt install`, by design — it
proves the "no container required" path works.

## Concurrency and queue policy

```yaml
concurrency:
  group: ${{ github.workflow }}-${{ github.ref }}
  cancel-in-progress: true
```

Push twice in a row to a PR: the older run is cancelled. This is
fine because every job is reproducible from inputs alone.

Nightly jobs (`e2e-replay`, `fuzz`, `cross-platform`) run on
`schedule: cron: '0 5 * * *'` (05:00 UTC). They do **not** cancel
each other; each completes or times out independently.

## Boundary enforcement

The one-way dependency (`iouring-net-server → iouring-net-lib`) is
enforced **mechanically in CI**, not by reviewer vigilance. Six
checks layer across the source tree, the configure step, and the
installed/build artifacts:

### 1. Sibling source tree absent during product build

Each CI job builds the product in a workspace that does **not**
contain `iouring-net-lib`'s source tree. The library is installed to
a temporary prefix (`$RUNNER_TEMP/lib-prefix`); the product clone is
the only thing on the runner filesystem the product job can see.

```yaml
# .github/workflows/build.yml (sketch)
- name: install library (out-of-tree)
  run: |
    git clone --depth 1 --branch ${LIB_TAG} \
        https://example.invalid/iouring-net-lib.git "$RUNNER_TEMP/lib-src"
    cmake -S "$RUNNER_TEMP/lib-src" -B "$RUNNER_TEMP/lib-build" \
          -DCMAKE_INSTALL_PREFIX="$RUNNER_TEMP/lib-prefix"
    cmake --build "$RUNNER_TEMP/lib-build" --target install
    rm -rf "$RUNNER_TEMP/lib-src" "$RUNNER_TEMP/lib-build"
- name: checkout product
  uses: actions/checkout@v4
- name: sanitize environment
  run: |
    # Strip env vars that can silently inject include paths the
    # CMake assert below cannot observe. These ARE env vars.
    echo "CPATH=" >> "$GITHUB_ENV"
    echo "CPLUS_INCLUDE_PATH=" >> "$GITHUB_ENV"
    echo "C_INCLUDE_PATH=" >> "$GITHUB_ENV"
    echo "CMAKE_INCLUDE_PATH=" >> "$GITHUB_ENV"
- name: configure product
  env:
    CMAKE_PREFIX_PATH: ${{ runner.temp }}/lib-prefix
  # CMAKE_FIND_USE_*_REGISTRY are CMake variables, NOT env vars —
  # pass them with -D on the configure line, not via GITHUB_ENV.
  # This disables the user/system package registries so a stale
  # build-tree iouring_netConfig.cmake cannot satisfy find_package.
  run: |
    cmake -S . -B build \
          -DCMAKE_FIND_USE_PACKAGE_REGISTRY=FALSE \
          -DCMAKE_FIND_USE_SYSTEM_PACKAGE_REGISTRY=FALSE
```

Removing `lib-src` after install is intentional: any product-side
`#include "../iouring-net-lib/src/..."` would now fail at compile
time, not at review time. The env sanitization plus the package
registry kill catch the next class of leaks — environment-driven
include injection and stale registry entries — that the assertions
in step 3 cannot see.

### 2. Grep-fail forbidden patterns (file-type-narrowed)

A small lint job runs early and fails the build on any of these
patterns appearing in **product source/config files** (not in docs
or markdown — those are explicitly allowed to discuss the patterns
as forbidden):

```bash
# .github/workflows/lint.yml (sketch)
PATTERNS=(
  '\.\./iouring-net-lib'                              # relative path into sibling
  'iouring-net-lib/src'                               # direct path into library source
  'add_subdirectory[^)]*iouring[-_]net[-_]?lib'       # embedding (single-line)
  'FetchContent_Declare[^)]*iouring[-_]net'           # bypassing install pipeline (single-line)
  'ExternalProject_Add[^)]*iouring'                   # same, via ExternalProject
  'CPMAddPackage[^)]*iouring'                         # CPM bypass
  'find_module.*iouring_net'                          # find-module instead of config
  'Findiouring_net\.cmake'                            # writing/shipping a find-module
  'CMAKE_MODULE_PATH.*iouring'                        # injecting a find-module path
  'target_include_directories.*iouring.*src'          # direct include into library src
  'include_directories.*iouring.*src'                 # same, global form
  '-I.*iouring.*src'                                  # CLI/-isystem injection
  'iouring_net_DIR.*(src|build|cmake)'                # pointing find_package at a build tree
)
for p in "${PATTERNS[@]}"; do
  if git grep -nE "$p" -- \
       ':(glob)**/*.[ch]' ':(glob)**/*.[ch]pp' \
       ':(glob)**/*.cc' ':(glob)**/*.cxx' \
       ':(glob)**/*.cmake' ':(glob)**/CMakeLists.txt' \
       ':(glob)**/CMakePresets.json' ':(glob)**/*.yml' \
       ':(glob)**/*.yaml' ':(glob)**/.gitmodules' \
       ':(exclude).github/workflows/lint.yml'; then
    echo "::error::forbidden pattern in product tree: $p"
    exit 1
  fi
done

# Separate two-pass check for `find_package(iouring_net ...)` calls
# missing the `CONFIG` keyword. POSIX ERE has no lookahead, so this is
# split: find all find_package lines, awk-filter those that do NOT
# contain CONFIG. (Avoids depending on `git grep -P` / PCRE.)
git grep -nE 'find_package\s*\(\s*iouring_net' -- \
     ':(glob)**/*.cmake' ':(glob)**/CMakeLists.txt' \
     ':(exclude).github/workflows/lint.yml' \
  | awk -F: '!/CONFIG/{print "::error::find_package(iouring_net) without CONFIG at " $1 ":" $2; bad=1} END{exit bad}'

# .gitmodules can't contain an iouring entry at all.
if [ -f .gitmodules ] && grep -qE 'iouring' .gitmodules; then
  echo "::error::.gitmodules references iouring; submodule embedding is forbidden"
  exit 1
fi
```

The file-type allowlist (`*.c`, `*.cpp`, `*.cmake`, `CMakeLists.txt`,
`*.yml`, `.gitmodules`) replaces the prior `docs/` / `wiki/` exclude
list. Markdown discussion of forbidden patterns is automatically
allowed; new source-tree directories get the right behavior by
default.

**Multi-line CMake hazard:** the regex catches single-line `add_subdirectory(... iouring ...)`
but a developer could write
```
add_subdirectory(
  ../iouring-net-lib
)
```
Two-line forms are caught by the **path** patterns
(`\.\./iouring-net-lib`, `iouring-net-lib/src`) which match the
argument on its own line. If a contributor sneaks in a fully
indirect form (variable holding the path), step 3 still catches
the resulting include resolution.

### 3. CMake install-prefix assertion (canonical-path)

After `find_package(iouring_net CONFIG REQUIRED)` resolves, CMake
canonicalizes every interface include dir and asserts each is
**under the install prefix's `include/` subtree** — computed from
the resolved package's location, not from any whitelist of "known
good" prefixes:

```cmake
# product CMake, immediately after find_package:
get_filename_component(_iouring_pkg_dir
  "${iouring_net_DIR}" REALPATH)
# iouring_net_DIR is <prefix>/lib/cmake/iouring_net — climb to <prefix>:
get_filename_component(_iouring_prefix
  "${_iouring_pkg_dir}/../../.." REALPATH)
set(_iouring_inc "${_iouring_prefix}/include")

get_target_property(_iface iouring_net::iouring_net
                    INTERFACE_INCLUDE_DIRECTORIES)
foreach(_d IN LISTS _iface)
  if(_d MATCHES "\\$<")
    # Generator expressions can hide a bad path. Resolve as best we
    # can; if we cannot strip the expression, treat as failure.
    string(REPLACE "$<BUILD_INTERFACE:" "" _stripped "${_d}")
    string(REGEX REPLACE "\\$<[^>]+:" "" _stripped "${_stripped}")
    string(REGEX REPLACE ">" "" _stripped "${_stripped}")
    if(_stripped MATCHES "\\$<")
      message(FATAL_ERROR
        "boundary violation: interface include dir contains an "
        "unresolved generator expression: ${_d}")
    endif()
    set(_d "${_stripped}")
  endif()
  get_filename_component(_d_real "${_d}" REALPATH)
  # Require an EXACT match or a path under the install include dir
  # WITH a `/` boundary. Plain prefix-match would let
  # `/prefix/include_evil` pass because it starts with `/prefix/include`.
  if(NOT _d_real STREQUAL "${_iouring_inc}"
     AND NOT _d_real MATCHES "^${_iouring_inc}/")
    message(FATAL_ERROR
      "boundary violation: iouring_net::iouring_net interface include "
      "${_d_real} is NOT under the resolved install prefix "
      "${_iouring_inc}. find_package probably picked an in-tree "
      "fallback or a build-tree package registry entry. Check "
      "CMAKE_PREFIX_PATH and disable CMake's package registries.")
  endif()
endforeach()
```

`file(REAL_PATH)`/`get_filename_component(... REALPATH)` follows
symlinks and resolves `..`, so a renamed source fork (e.g.,
`~/forks/netlib/`) cannot bypass via a symlinked or relative path.

### 4. Build-artifact scan

After configure, scan generated build files for any reference to
the library source/build directories that should have been
discarded. This catches the case where step 1's filesystem cleanup
happened but a CMake variable, environment variable, or registry
entry still pointed at the source tree:

```bash
# .github/workflows/build-artifact-scan.yml (sketch)
ARTIFACTS=(
  build/compile_commands.json
  build/CMakeCache.txt
  build/build.ninja
  build/CMakeFiles/**/link.txt
)
FORBIDDEN=(
  '/lib-src/'       # the discarded clone dir
  '/lib-build/'     # the discarded build dir
  'iouring-net-lib/src'
  'iouring-net-lib/build'
)
for f in "${ARTIFACTS[@]}"; do
  for p in "${FORBIDDEN[@]}"; do
    if grep -q "$p" "$f" 2>/dev/null; then
      echo "::error::build artifact $f contains forbidden path $p"
      exit 1
    fi
  done
done
```

This catches `-I`, `-isystem`, linker `-L`, and stale CMake-cache
entries that target-property inspection misses.

### 5. Library install-manifest check (runs in the LIB job)

Before tagging or publishing the library, install to a temp prefix
and assert no private headers leaked into the install tree:

```bash
cmake -S iouring-net-lib -B lib-build \
      -DCMAKE_INSTALL_PREFIX="$RUNNER_TEMP/lib-manifest-check"
cmake --build lib-build --target install

# Any path containing /internal/ or ending in _internal.* is private
# and must NOT appear in the install tree.
if find "$RUNNER_TEMP/lib-manifest-check" \( \
       -path '*/internal/*' \
    -o -name '*_internal.h' \
    -o -name '*_internal.hpp' \) -print | grep -q .; then
  echo "::error::private header leaked into install tree"
  find "$RUNNER_TEMP/lib-manifest-check" \( \
       -path '*/internal/*' \
    -o -name '*_internal.h' \
    -o -name '*_internal.hpp' \)
  exit 1
fi
```

With `FILE_SET HEADERS` driving the install (see
[`iouring-net-lib/docs/09-project-split.md`](../../2026-05-14-project-split.md)
§ "The contract surface"), this should always pass — but the check
exists as a backstop in case someone adds a FILE_SET entry pointing
at an internal path by mistake.

### 6. Installed-consumer smoke test

A minimal product-side job verifies the library is consumable from
scratch:

```cmake
# tests/install-consumer-smoke/CMakeLists.txt
cmake_minimum_required(VERSION 3.25)
project(iouring_net_consumer_smoke LANGUAGES CXX)
find_package(iouring_net 0.0.1 CONFIG REQUIRED)
add_executable(consumer_smoke main.cpp)
target_link_libraries(consumer_smoke PRIVATE iouring_net::iouring_net)
```

```cpp
// main.cpp — touches every intended public header by include path.
#include <iouring_net/types.h>
#include <iouring_net/error/expected.h>
#include <iouring_net/diagnostic/profiler_scope.h>
#include <iouring_net/sds/cstr_hash_map.h>
#include <iouring_net/sds/malloc_vector.h>
#include <iouring_net/sds/ring_buffer.h>
#include <iouring_net/sync/atomic.h>
int main() { return 0; }
```

The job runs **after** removing the library source/build dirs and
the env sanitization from step 1, so it proves the install package
is sufficient on its own.

## Failure routing

| Failure                             | Action                                                              |
|-------------------------------------|---------------------------------------------------------------------|
| `default-*` red                     | Block merge                                                         |
| `floor-jammy` red                   | Block merge (regression in declared support)                        |
| `tsan-noble` red                    | Block merge                                                         |
| `clang-noble` red                   | Block merge unless flagged compiler-bug-acknowledged                |
| `release-noble` red                 | Block merge                                                         |
| `e2e-replay` red                    | Open an issue; don't auto-block (slow tests, flakes are real)       |
| `fuzz` red (crash or sanitizer hit) | Open a P0 issue with the minimized reproducer attached              |
| `cross-platform` red                | Block release; PR-block depends on whether the PR touches `proto/`  |
| `lint` red (forbidden boundary pattern) | Block merge — boundary violation                                |
| `cmake-install-prefix-assert` red   | Block merge — `find_package` resolved to in-tree source             |
| `build-artifact-scan` red           | Block merge — stale path in compile_commands.json / CMakeCache.txt  |
| `lib-install-manifest` red          | Block library release — private header leaked into install tree     |
| `install-consumer-smoke` red        | Block merge — installed library is not consumable from scratch      |

The "block merge" jobs are configured as required checks in
the GitHub branch protection rule for `main`.

## Things we do not do in CI

- **No publishing of binaries.** v1 is source-and-build. Binary
  artifacts arrive at v1.0 release time.
- **No deploy step.** There is no deployable surface in v1 (no managed
  fleet, no Docker registry of the product binary).
- **No coverage upload to a third party.** `gcovr` runs locally and on
  the nightly E2E job; the report is a job artifact, not pushed to
  Codecov / Coveralls.
- **No security-scanning step beyond ASan/UBSan/TSan.** Codeql /
  similar can be added later; not v1.
